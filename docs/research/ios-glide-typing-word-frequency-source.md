# English word-frequency source for iOS glide typing

Research date: 2026-08-27. This note resolves the dictionary-source part of [issue #12](https://github.com/nmarch213/Hex/issues/12). It considers only sources that can produce a small, offline, frequency-ranked English resource for the personal Hex iOS keyboard. This is an engineering license review, not legal advice.

## Decision

Use a generated 20,000-entry subset of SymSpell's `frequency_dictionary_en_82_765.txt`, pinned to commit [`c239062ae02961df18ab7da1671d01b4388204e0`](https://github.com/wolfgarbe/SymSpell/tree/c239062ae02961df18ab7da1671d01b4388204e0), for the first glide-decoder prototype.

SymSpell is the simplest practical choice because its source is already a two-column, lowercase word/count file; its vocabulary was intersected with SCOWL to filter Google Books OCR and spelling noise; and a 20,000-row prefix is only about 330 KB before app-resource compression. The repository tells consumers to copy the dictionary into their projects and declares MIT terms, while documenting Google Books Ngram and SCOWL as the dictionary's inputs. Those upstream notices must travel with Hex's derived resource; the root MIT license alone is not a complete attribution record. [SymSpell dictionary documentation](https://github.com/wolfgarbe/SymSpell/blob/c239062ae02961df18ab7da1671d01b4388204e0/README.md#frequency-dictionary), [SymSpell MIT license](https://github.com/wolfgarbe/SymSpell/blob/c239062ae02961df18ab7da1671d01b4388204e0/LICENSE), [Google Books Ngram export license](https://storage.googleapis.com/books/ngrams/books/datasetsv3.html), [SCOWL v1 license and credits](https://wordlist.aspell.net/scowl_v1-readme/)

Start at 20,000 entries rather than making dictionary size configurable. That maximizes vocabulary coverage within issue #12's proposed 5,000–20,000 range while keeping the raw resource below 330 KB. Reduce it to 10,000 only if physical-device latency or memory measurements fail the prototype's explicit regression limits; a larger candidate set can add ambiguity and decoder work, so the target phone remains the authority.

## Distribution caveat

The recommendation above is for Hex's personal prototype and source repository. Both candidate chains contain Creative Commons material, and both CC BY 3.0 and CC BY-SA 4.0 prohibit imposing technological measures that legally restrict the licensed freedoms. Creative Commons' archived 4.0 drafting discussion specifically identifies iOS App Store FairPlay as a measure that **may** create a license conflict and says the question needs further research; it does not state a settled rule. Before a public App Store release, obtain legal review or explicit additional permission, or replace the resource with a source whose distribution terms settle that question. [CC BY 3.0 terms](https://creativecommons.org/licenses/by/3.0/), [CC BY-SA 4.0 terms](https://creativecommons.org/licenses/by-sa/4.0/), [Creative Commons FairPlay discussion](https://wiki.creativecommons.org/wiki/4.0/Technical_protection_measures)

## SymSpell provenance and uncertainty

The provenance is identifiable but not reproducible from raw corpora. SymSpell names Google Books Ngram and SCOWL, links the Version 2 Ngram downloads, and says that it used intersection plus “additional filters.” It does not pin the exact Google corpus files, SCOWL revision, or generation script used to produce the dictionary. Pinning the resulting file and recording its SHA-256 therefore protects Hex from silent upstream changes, but it does not reconstruct the original build. [SymSpell provenance statement](https://github.com/wolfgarbe/SymSpell/blob/c239062ae02961df18ab7da1671d01b4388204e0/README.md#frequency-dictionary)

There is also a licensing ambiguity to preserve explicitly: SymSpell's root MIT file does not separately say that the composite dictionary is relicensed solely under MIT, while the dictionary documentation continues to identify and link the upstream licenses. For the prototype, treat the resource as separately licensed data and carry all three notice chains. Do not rely on the SymSpell MIT notice alone for a public release. [SymSpell MIT file](https://github.com/wolfgarbe/SymSpell/blob/c239062ae02961df18ab7da1671d01b4388204e0/LICENSE), [SymSpell dictionary sources](https://github.com/wolfgarbe/SymSpell/blob/c239062ae02961df18ab7da1671d01b4388204e0/README.md#frequency-dictionary)

The pinned source SHA-256 is `c604e1121e398ae7c7fbf777f11e0a0f2fa66eda932cb9fba1321466cf3acd7b`. Its filename is stale: the current file has 82,834 logical records, not 82,765. After the original 82,767 records, it appends 65 apostrophe-containing contractions with the same count of 300,000, followed by `covid` and `hi`; one appended token is the apparent typo `you'v`. Those appended contractions fall outside a frequency-ranked 5,000–20,000 subset and should not be silently mixed into the initial prior. If the fixture corpus requires contraction output, add a small, reviewed contraction mapping as a separate decoder decision. [Pinned dictionary tail](https://github.com/wolfgarbe/SymSpell/blob/c239062ae02961df18ab7da1671d01b4388204e0/SymSpell/frequency_dictionary_en_82_765.txt)

Google's source is book usage rather than current mobile typing, so the frequency prior will be imperfect for chat slang and product names. SCOWL improves lexical validity, not conversational recency. Treat the dictionary as a baseline for the measured prototype, not as a claim of Apple-QuickPath-quality language modeling. [Google Ngram corpus description](https://books.google.com/ngrams/info), [SCOWL purpose and size guidance](https://wordlist.aspell.net/scowl_v1-readme/)

## Required derivation and notices

Generate the checked-in resource deterministically rather than editing a copied list by hand:

1. Download the pinned SymSpell file and verify the SHA-256 above.
2. Decode UTF-8, strip the leading BOM, require a unique term matching `^[a-z]+$` and a positive integer count, order by descending count with a stable lexical tie-break, and take exactly 20,000 entries.
3. Record the source commit, source SHA-256, transformation, generated row count, and generated SHA-256 next to the resource.
4. Bundle a third-party notice with the keyboard resource that preserves Wolf Garbe's MIT notice, attributes Google Books Ngram Viewer under CC BY 3.0 with a source and license link and says Hex filtered/truncated the data, and preserves SCOWL v1's copyright, permission, source, and disclaimer notices. Do not describe the generated dictionary as solely MIT-licensed. [SymSpell MIT condition](https://github.com/wolfgarbe/SymSpell/blob/c239062ae02961df18ab7da1671d01b4388204e0/LICENSE), [CC BY 3.0 attribution requirements](https://creativecommons.org/licenses/by/3.0/), [SCOWL notice requirements](https://wordlist.aspell.net/scowl_v1-readme/)

These commands reproduce the source measurements used above:

```bash
wc -lc frequency_dictionary_en_82_765.txt
awk 'END { print NR }' frequency_dictionary_en_82_765.txt
shasum -a 256 frequency_dictionary_en_82_765.txt
sed -n '1,5000p' frequency_dictionary_en_82_765.txt | wc -lc
sed -n '1,10000p' frequency_dictionary_en_82_765.txt | wc -lc
sed -n '1,20000p' frequency_dictionary_en_82_765.txt | wc -lc
```

The source decision does not establish decoder quality. [Issue #12](https://github.com/nmarch213/Hex/issues/12) still requires real iPhone path fixtures, top-three accuracy, alternate selection, last-word replacement, latency, and extension-memory gates before this can be called usable.
